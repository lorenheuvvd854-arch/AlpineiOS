# Можно ли запустить AlpineiOS без JIT

Короткий ответ: **нет, не в текущей архитектуре.** JIT в этом проекте — не
ускоритель, а сам движок исполнения гостевого кода. Без него виртуальная машина
не стартует вообще.

Ниже — почему так, что именно потребуется для честного «без JIT» и почему
Kernarium не является готовой заменой.

## 1. Что делает JIT в AlpineiOS

`core/translate.c` — транслятор гостевых инструкций ARM64 в инструкции хоста
ARM64. Гость и хост имеют одну и ту же систему команд, поэтому транслятор не
эмулирует каждую инструкцию, а копирует её (с правками адресов, PC и т.п.) в
буфер кода. Затем `core/dispatch.c` передаёт управление этому буферу через
`host/enter.S`.

Отсюда два следствия:

1. Гостевые страницы кода должны стать **исполняемыми** страницами хоста.
2. Пока код не переведён, гость выполнить нельзя: «интерпретатора на запасной
   путь» в проекте нет.

`hv_winvm_create()` вызывает `hv_machine_init_jit(&m, rx, rw, bytes)`
(`host/winvm.c`) и без исполняемого региона возвращает ошибку
`Cannot initialize ARM64 JIT region (is JIT active?)`.

## 2. Почему на iOS для этого нужен отладчик

iOS не разрешает приложению создавать одновременно записываемые и исполняемые
страницы (W^X). Штатный путь — entitlement `com.apple.security.cs.allow-jit` +
`MAP_JIT`, но с ним приложение не устанавливается на обычный iPhone.

Проект использует путь Henge/StikJIT (`ios/Sources/Native/winios_jit.c`):

- приложение должно иметь флаг `CS_DEBUGGED` (проверяется через `csops`,
  syscall 169);
- на iOS 26/27 (TXM) отладчик должен обслужить `BRK #0x69`, выдать
  dual-mapped регион RX/RW и пройти самотест;
- после этого приложение может отключить отладчик и работать дальше.

Именно поэтому в README упоминаются `launch_on_iphone.sh` (LLDB с Mac) и кнопка
**Enable JIT with StikDebug** (StikDebug на самом телефоне). Это не прихоть
разработчика, а требование iOS к самому способу исполнения кода.

## 3. Что значит «без JIT» технически

Единственный способ исполнять ARM64-код без генерации машинного кода — писать
**интерпретатор** этой системы команд. Не «отключить JIT-флаг», а заменить
транслятор на цикл «декодировать инструкцию → выполнить её в C».

Объём работы для загрузки Linux + Phosh:

| Компонент | Что нужно |
|---|---|
| Целочисленный A64 | ~400 инструкций, флаги, сдвиги, ветвления |
| Загрузка/запись | все варианты адресации, выравнивание, MMU/TLB |
| Исключения | SVC, IRQ/FIQ, abort, sysreg-ы EL0/EL1 |
| FP/NEON | ~600 инструкций; на NEON завязаны pixman, cairo, Qt, Mesa |
| Атомарные операции | LDXR/STXR, LSE-расширения |
| Отладка | сравнение трасс с JIT-сборкой |

Это десятки тысяч строк и месяцы работы. Ожидаемая скорость — в 5–20 раз ниже
JIT. Для сравнения: UTM SE (интерпретатор TCG/TCI) грузит Linux в несколько раз
дольше JIT-сборки, а TCTI в среднем в 2,8–5,6 раза медленнее JIT. Phosh с
программным рендерингом (pixman/cairo, см. `scripts/guest/enable_native_display.sh`)
при такой скорости практически неработоспособен.

Важно: интерпретатор не требует исполняемых страниц, поэтому такие сборки
проходят проверку App Store — так и живёт UTM SE. Но это отдельный продукт, а
не флаг в текущем движке.

## 4. Почему Kernarium — не готовое решение

Kernarium использует другую архитектуру:

- ядро Linux собирается как **UML** (User-Mode Linux) и исполняется нативно на
  arm64, без эмуляции;
- userspace обслуживается интерпретатором в стиле iSH (для x86-гостевых
  бинарников), а не полноценной виртуальной машиной;
- нет VirtIO GPU, Metal-вывода, NVMe-контроллера и UEFI: это терминал/рабочий
  стол, а не VM с аппаратной моделью.

Перенести этот подход сюда нельзя: здесь нужен именно полный системный
эмулятор с virtio-gpu и Metal, иначе Phosh не выведет кадры. Кроме того, UML на
iOS — отдельный большой порт ядра.

## 5. Что реально можно сделать без Mac

JIT требует отладчика, но **не требует Mac**. StikDebug запускается на самом
iPhone и умеет включать JIT для подписанного development-сертификатом
приложения. Пошаговая инструкция для Windows: [NO-MAC.ru.md](NO-MAC.ru.md).

Это единственный способ получить текущую скорость и работающий Phosh на
устройстве без компьютера с Xcode.

## 6. Если всё же нужен настоящий no-JIT

Порядок работ, который имеет смысл:

1. Вынести исполнение из `core/dispatch.c` в сменный backend (`jit` / `interp`).
2. Реализовать целочисленное ядро A64 + доступ к памяти через существующие
   MMU/TLB (`core/mmu.c`, `core/memop.c`).
3. Добавить исключения и системные регистры (`core/exception.c`,
   `core/sysreg.c`).
4. Добавить FP/NEON — самый большой и рискованный этап.
5. Прогнать `make test-core`, затем загрузку Linux в QEMU-профиле и только
   потом на устройстве.

До выполнения этих пунктов любая сборка «без JIT» либо не запускает VM, либо
является другим эмулятором. Этот форк честно остаётся JIT-сборкой; его
изменения касаются времени загрузки и установки без Mac.
