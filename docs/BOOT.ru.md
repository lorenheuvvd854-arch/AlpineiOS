# Ускорение загрузки

Изменения этого форка касаются времени до появления Phosh и не меняют движок
исполнения. JIT по-прежнему обязателен.

## Что сделано

`scripts/guest/tune_boot.sh` добавляется в образ при провижининге
(`scripts/prepare_phosh.sh`) и делает три вещи:

1. **Убирает сервисы без оборудования.** В VM нет Bluetooth, модема и Wi-Fi,
   поэтому `bluetooth`, `modemmanager`, `wpa_supplicant`, а также `chronyd`,
   `crond`, `sshd`, `avahi-daemon`, `cupsd`, `saned` исключаются из runlevel
   `boot`/`default`. Сетевой стек, `dbus`, `seatd` и графика не затрагиваются.
2. **Сокращает вывод ядра.** В kernel command line добавляются
   `quiet loglevel=3 nowatchdog mitigations=off`. Каждая строка лога уходит в
   эмулируемый PL011 UART, а это заметная доля времени на эмулируемом CPU.
   `mitigations=off` безопасен для гостя под VM.
3. **Монтирует корень с `noatime`.** Эмуляемый NVMe дорог для записи, а
   access time в этом образе никому не нужны.

Скрипт идемпотентен: повторный запуск ничего не ломает и не дублирует
параметры. Если в образе нет ни GRUB, ни extlinux, шаг с cmdline пропускается.

## Как проверить эффект

На устройстве откройте трёхпальцевое меню → **Serial console** и выполните:

```sh
cat /proc/uptime          # секунды с начала загрузки ядра
dmesg | head -n 40        # таймстемпы ранней загрузки
rc-status default         # какие сервисы реально стартовали
```

Сравнивайте одинаковые условия: первый запуск после установки всегда дольше,
потому что распаковывается диск и ставятся приложения. Для честного сравнения
нужен второй и последующие запуски.

## Что сознательно не менялось

- **Число vCPU.** На телефоне используется 1 vCPU. Движок умеет SMP
  (`spawn_secondaries`), но SMP-путь не покрыт тестами, а `big_lock` по
  умолчанию выключен. Включать второй vCPU вслепую — риск получить гонки в
  MMIO и случайные падения. Это следующий кандидат на оптимизацию, но только
  после тестов на устройстве.
- **Формат `hvsparse` и распаковка.** Распаковка выполняется один раз, и её
  ускорение не влияет на последующие загрузки.
- **UEFI.** Прошивка EDK2 и NVRAM не трогались: неверная правка `vars.fd`
  легко превращает телефон в кирпич по загрузке, а проверить это без устройства
  невозможно.

## Откат

Вернуть сервисы можно вручную:

```sh
rc-update add bluetooth default
rc-update add modemmanager default
```

Параметры ядра убираются из `/etc/default/grub` (или
`/boot/extlinux/extlinux.conf`) и regenerated командой `grub-mkconfig`.
